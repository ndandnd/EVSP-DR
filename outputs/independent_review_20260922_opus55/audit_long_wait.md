## Verified implementation

1. **The default direct-connection cap really is 57 minutes.** Both baseline runners call `build_problem` without overriding `max_trip2trip_min` (`src/exact_pricer_expanded.py:1641–1642` at both baseline pins); strict does likewise ([runner:992](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/run_capacity_speed_event_cg.py:992)). Its default is 57 and is passed to `build_dag` ([builder:169](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/audit_giro_known_columns.py:169), [builder:273](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/audit_giro_known_columns.py:273)). `build_dag` discards a trip pair when **next start − previous end >57**, not when idle time *after subtracting deadhead* exceeds 57 ([DAG:793](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/pricing_dp_og.py:793)). That file is byte-identical across all three pins.

2. **The event graph inherits the cap.** Its `_split_arcs` copies the supplied adjacency; `_direct_candidates` considers only those `trip_trip` pairs. There is no later unrestricted direct-wait insertion (`a0e0bb7:src/event_pricer_network.py:247–267,434–467`; `e091a4d:247–267,392–425`; strict [split:359](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/event_pricer_network.py:359), [direct:556](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/event_pricer_network.py:556)). A sink return ends the route; it cannot re-enter the depot source to bridge the same duty.

3. **An inter-trip station bridge requires positive grid charging.** Every bridge uses `range(entry + 1, len(self.grid))` and `energy = grid[target] − grid[entry]`: at least one SOC step, **2.5 kWh at the audited settings**. There is no `target=entry` station-wait edge (`a0e0bb7:event_pricer_network.py:475–546`, especially495; `e091a4d:433–504`, especially453; strict [charge:597](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/event_pricer_network.py:597), especially617). Thus two consecutive serviced trips separated by more than 57 minutes can connect only through an admissible positive-charge bridge. This is conditional on feasible station travel, time and SOC.

4. **The broad statement “a full battery cannot wait” is false.** Full-SOC buses can wait before their first trip, and a retained direct pair can include idle time. The precise omission is a **zero-charge inter-trip station bridge when arrival is at the top represented SOC level**. At that level the charging loop is empty. Strict's 239.01-kWh battery/2.5-kWh grid has top level 237.5 kWh, so “top grid level” is more precise than “physically full” ([grid:246](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/event_pricer_network.py:246), [source:529](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/src/event_pricer_network.py:529)). A full bus may also spend energy on a detour and regain charging headroom; the code does not rule out every alternative route.

## Executed small counterexample

I extracted each pin's complete `src` tree to a temporary directory and constructed its actual `build_dag` + packed `EventExpandedNetwork`; no LP, MIP or pricing optimization ran. Two trips, zero deadhead, one PARX bridge: first trip 10–20 min, second starts at 20+gap and lasts10 min; second energy 1 kWh. Flat prices, SOC step 2.5, event block 5. Baseline battery/reserve/power 240/0/240; strict 239.01/35.8515/PARX 60. Assertions passed at all three pins:

| Gap | First-trip energy | Direct cap | Direct connection | Station connection |
|---|---:|---:|---|---|
|57 min|0 kWh|57 min|Present at top SOC|Absent at top SOC|
|58 min|0 kWh|57 min|Absent|Absent at top SOC|
|58 min|2.5 kWh|57 min|Absent|Present, charges exactly 2.5 kWh|
|58 min|0 kWh|180 min|Present at top SOC|Absent at top SOC|

For the third case, charging ends at 20.625 min in baseline or 22.5 min in strict, while the next trip starts at 78 min. **Most of the gap is uncharged waiting**: the model does not require charging throughout a long layover. In every case, a full-battery depot source could directly reach the later first trip. The zero-energy first trip isolates the boundary state; this is a synthetic representability witness, not evidence that this exact state occurs in a production duty. Raising only the connection cap restores a time/SOC-feasible zero-charge path, proving the restriction matters relative to a model allowing unrestricted idle connections.

## Intent, existing tests and certificate scope

**Documented restriction:** `EXACT_PRICER.md:13–15`, identical at all three pins, explicitly describes the reused loader as a restricted graph with 57-minute trip gaps and full-horizon station waiting ([document](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/EXACT_PRICER.md:13)). The DAG comment calls it pruning of long idle gaps. This establishes a deliberate implementation/model restriction, not a new cache/packed-arc regression. I found no inspected specification establishing 57 minutes or mandatory positive charging as a GIRO operating rule, or proving the pruning harmless.

Existing [matching test:72](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/tests/test_matching_init.py:72) explicitly requires positive charging for a station bridge; it supports historical intent but is not an independent completeness test for the event graph. A separate [continuous fixed-duty test:394](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/tests/test_fixed_duty_continuous_optimizer.py:394) permits a zero-charge station waypoint, illustrating that the repository contains a broader physical realization model too. Those tests were inspected, not executed here.

**Reporting consequence:** retain certificates scoped to the stated conservative event/SOC graph, including its connection restrictions. The work order explicitly requires exactness claims to name their route space ([convention:130](/Users/nadan/Documents/projects/demandresponse/.codex-work/strict-graph-reuse-20260922/EVENT_BASED_PRICER_WORKORDER_20260820.md:130)). If the intended comparison model allows arbitrary feasible idle connections or zero-charge station layovers, the audited graph omits such routes; its certificate does not establish optimality for that broader model. Whether to change that intended route space is a model decision, and the fleet/cost impact requires a separately controlled comparison. No production change is proposed by this audit.
