## Immediate implementation and test priorities

1. Make the generic column identity capacity-aware before combining strict physics with baseline full-pool inheritance: use ordered trips plus canonical station-time occupancy (and a tariff/energy realization discriminator where cost coefficients can differ). Add a regression in which two routes serve the same trips but occupy different charger minutes and only their combination makes the capacity MIP feasible.
2. Run one minimal controlled capacity-selector pair on the already frozen certified k1 combined case: same commit containing `550bc795`, same input/hashes, one process per arm, selector `scan` versus `prefix-memo`, flat tariff first. Require identical route keys, iteration trace, terminal reduced cost, pool hash, MIP fleet/bound and physical-capacity audit; report completed-iteration time and censoring separately. Then repeat the same case with a two-block variable tariff and PARX 60 kW to exercise the repaired cost contract.
3. For strict physics, run E1-short-k2 with actual 18E1 battery, 15% floor, PARX 60 kW and charger counts, generating multiple negative and near-zero occupancy-distinct routes per iteration. Require a pricing certificate or label-space limitation stated in the result, a capacity-aware saved pool, fleet incumbent/bound, and replay of every selected cover route after duplicate service is repaired.
4. Only after defining whether 65% is a soft recharge target, a hard post-charge minimum, or an end-of-duty condition, add it to the same E1-short-k2 control. A per-vehicle hard constraint cannot be inferred from the existing aggregate terminal pilot.
5. Instrument/checkpoint parent-graph construction before another 750-trip shared build. Job 42509 shows memory was not the limiting resource; another larger-memory request would not address the observed 12.5-hour startup timeout.
